## 1. 目标

企业员工现在要在多个系统之间搬运文件、查资料、找数据、拼报告，过程不可追溯，结果无法复用。Riccon 把这件事收进一个租户隔离的云工作空间：员工上传办公文件、提问、调用已授权工具、在关键动作上审批，Agent 产出带引用的回答与可保存的报告；平台侧统一管理模型、知识库、MCP 与权限，并留下可审计的记录。M02 要证明的不是"能聊天"，而是"员工的一条完整办公任务能在可审计、可隔离的前提下跑完"。

## 3. MVC：J1 + J2

MVC 是两条相连的员工旅程：J1 解决"我的文件能不能被理解和引用"，J2 解决"一次带外部数据与人工审批的任务能不能产出可交付报告"。J2 复用 J1 的文件与引用能力，因此两条旅程共同构成一条关键旅程。

### J1 通用问答与文件处理

**输入**

- 员工用租户内账号登录，进入云工作空间并新建会话。
- 上传 PDF、Word（.docx）、Excel（.xlsx）、PNG/JPEG 文件；M02 默认单文件 ≤ 200 MB、单次会话 ≤ 5 个文件。
- 用自然语言提问，问题可指向某个已上传文件，也可指向租户知识库。

**可见产物**

- 每个文件有明确的解析状态：处理中、成功、失败（含原因与下一步）。
- 提交问题后 3 秒内出现首字，回答流式增长；员工可中途停止，已生成内容保留。
- 回答附带引用列表，每条引用可定位到文件名与页码/工作表/段落；点击可打开对应位置。
- 知识库无命中时明确提示"未检索到相关资料"，不展示伪造引用。
- 会话与上传文件保存在工作空间，可再次打开并继续提问。
- 失败态：不支持的格式、超限、解析失败、模型失败，均显示原因与可重试入口，且不丢失已上传文件。

**必须存在的证据**

- 一条可回放的 E2E 记录：登录 → 上传 → 解析成功 → 提问 → 首字 → 引用 → 停止 → 重新打开会话。
- 会话运行详情中可见模型调用记录：模型标识、开始/结束时间、结果状态。
- 审计记录覆盖文件上传、文件删除、会话创建、模型调用。
- 引用与源文件的对应关系可在界面上复现，不依赖测试代码或日志推断。

### J2 市场调研报告

**输入**

- 员工在工作空间新建"市场调研报告"任务，输入主题（例：某行业市场规模与竞争格局）。
- 选择一个已授权给本租户的 MCP 工具用于取数；M02 只要求 1 个工具。
- 任务运行到工具调用前，员工收到审批请求。

**可见产物**

- 任务详情显示当前阶段：检索 → 工具取数 → 审批 → 生成报告，阶段切换可见。
- 检索阶段展示命中的资料条目、来源与片段，并标注引用。
- 工具阶段展示 1 次 MCP 调用记录：工具名、入参摘要、结果摘要、耗时、状态；失败时显示原因并可重试该阶段。
- 审批节点展示将要执行的动作、目标工具与数据范围；员工批准后继续，拒绝后任务终止，记录审批人与时间。
- 报告产物保存在工作空间，含标题、摘要、分节正文、引用清单、数据来源；可再次打开，引用清单中的每条来源都能在运行记录中找到。
- 失败态：检索无结果提示调整主题且不进入生成；MCP 超时、审批拒绝、报告生成失败均有明确状态、保留已完成阶段记录、可重试且不产生重复产物。

**必须存在的证据**

- 任务时间线：检索查询与命中、MCP 调用（工具、入参摘要、结果摘要、耗时、状态）、审批（人、时间、决定）、模型调用、产物版本。
- 审计记录覆盖 MCP 调用、审批动作、产物保存。
- 产物引用清单与任务时间线一一对应，可人工抽查。
- 两条 E2E 路径：审批通过产出报告；审批拒绝终止且无产物。

### M02 范围边界

- 包含：内置账号登录、租户与基础 RBAC、云工作空间、J1、J2、模型网关最小闭环（单一 OpenAI 兼容端点）、审计写入、基础可观测性。
- 不包含（按路线图后移）：OIDC/SSO 与部门数据范围（M03）、模型路由与配额（M04）、文档级 ACL 与 OCR（M05）、MCP 注册审批与凭据托管（M07）、可视化编排（M06）。

## 8. M03 / M10（M03b）验收标准

本节覆盖两个模块：M03「权限纵深与组织模型」（部门、数据范围、部门维度越权）与 M10「身份与审计纵深（M03b）」（OIDC、审计查询/导出、身份与导出越权）。8.5 给出 AC 归属与 gate 判定。

M03/M10 的用户可见结果：负责人能按部门组织人并共享空间，员工用企业账号（OIDC/SSO）登录且只看得到该看的，管理员能查审计、能导出且导出要审批，越权套件覆盖部门维度。编号用于任务拆解与 verifier 逐条对账；每条至少对应一条 E2E、集成或安全测试。AC 不规定实现方式。

### 8.1 范围内与范围外

**范围内**

| 能力           | M03 交付的用户可见结果                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 组织与部门     | 租户内创建/停用部门，账号归属唯一主部门，部门负责人管理本部门共享空间与成员可见范围                                        |
| 数据范围       | 会话、文件、报告按空间归属隔离：个人空间私有，部门空间按可见范围；跨部门与跨租户统一 404，不泄露存在性                     |
| OIDC/SSO       | 一个企业 IdP 的授权码 + PKCE 登录；账号按 issuer + subject 绑定；冲突、禁用、错误态有明确文案；复用 M02 会话层，不引入 JWT |
| 审计查询与导出 | 管理员按时间/动作/操作者/对象过滤并分页查看；只读；导出需他人审批，导出行为本身被审计；保留口径 ≥ 180 天                   |

- 多级部门树、跨部门项目组、一个账号多部门归属、负责人委派/多负责人、组织架构自动同步（SCIM/LDAP/HR）。
- 部门级/文档级知识库 ACL：M03 知识库仍是租户级共享，界面必须明示，不声称部门隔离（文档级 ACL 属 M05）。
- 多 IdP 并存与租户自助配置 IdP、IdP 组到角色自动映射、账号自动开通、按邮箱自动关联账号。
- MFA（威胁模型 M03 行列了 MFA，但模块 acceptance 未列，见 §9 OQ-6）。
- 平台管理员跨租户查看租户业务审计明细（I-07-1 的显式授权模型见 §9 OQ-13）。
- 审计哈希链/完整性证明（append-only 触发器与数据库最小权限仍是有效控制，见 §9 OQ-11）。
- 审计在线删除、导出常驻链接、导出文件内预览。
- M02 遗留：>2 MiB 产物下载、`commands.perf` 脚本、OpenAPI 契约漂移、ADR-0009/0014 文档收口（见 8.4）。

### 8.2 用户故事

- **员工（王敏，销售）**：我用企业账号登录，不用再记一套密码；进来只看到自己的个人空间和已加入的部门共享空间；看不到别的部门的东西，也看不出它们是否存在；登出后同事用我的电脑后退也回不到我的会话。
- **部门负责人（李强）**：我把本部门共享空间设成"本部门成员"或"指定成员"，随时加人减人；被移出的成员立刻进不来；我交接给同事后，自己不再有管理入口；每次变更都查得到记录。
- **平台管理员（赵蕾）**：我按时间、动作、操作者、对象筛审计，翻页不卡；要导出时先提交申请，另一位管理员批准后我才能下载，这次导出也出现在审计里；整页没有删除按钮，员工看不到这个菜单。
- **IT 运维（陈涛，私有化部署）**：我通过部署配置提供企业 IdP 的 issuer 与客户端凭据，不写进仓库、镜像或日志；配错时登录页给出可读原因，内置账号仍可登录兜底；M03 不新增运维界面。

### 10.2 用户故事

- **平台管理员（赵蕾）**：我把 CHAT 和 REPORT 的模型链按优先级排好，给每个供应商放多个 key；某条链路坏了会自动换下一个。我给租户设日/月配额，打开成本页就能看到哪个租户、哪个模型在花多少。密钥保存后我只看到掩码，页面、日志和报错里都不会出现明文。
- **租户管理员（李强）**：我只看到本租户的配额、当前用量和成本，知道是哪个限额用完了、什么时候重置；看不到其他租户的名称、金额或调用量。我不能改平台路由，也不希望看到密钥。
- **员工（王敏）**：我照常提问、做报告。模型切换时我不需要知道，也不希望看到供应商名称或英文错误。回答中途断了，已生成的内容要保留，我能直接重试；所有模型都不可用时，给我一句能看懂的话和一个重试入口。
- **IT 运维（陈涛）**：我在部署侧维护受管端点、出网允许列表和主密钥；我能用开关关闭路由、降级或配额执行，回到基线策略。回滚不需要改数据库结构，历史调用记录还能读；降级和配额拒绝有指标可看。

## 11. M05 知识库纵深验收标准

**T4 回滚约束（DEC-0034 已定）**
