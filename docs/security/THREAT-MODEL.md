# 威胁模型（T4）

- **所有者**：`riccon/architect`
- **适用版本**：M01 基线核对 + M02 设计目标（M03 以后标注为后置项）
- **状态**：M01 初稿，M02 gate 前由 `riccon/verifier` 按第 10 节逐条核对
- **关联文档**：`AGENTS.md` 合同（T4、数据、许可、审计约束）、`docs/PRODUCT.md`（J1/J2、M02 AC）、`docs/ARCHITECTURE.md`、`docs/CODING-STANDARDS.md`
- **关联决策**：ADR-0001（双部署物）、ADR-0003（租户上下文）、ADR-0005（MySQL 许可）、ADR-0006（密钥生命周期）、ADR-0007（审计事件）、ADR-0008（异步承载）、ADR-0009（租户隔离强制点）、ADR-0010（Flyway 归属）、ADR-0011（B-06 依赖例外）、DEC-0003（MySQL 驱动选择 C）

复审触发条件（任一发生即重开本文件）：新增外部集成或出网目标、引入新数据类别（生物特征、健康、财务明细）、认证方式变化（OIDC/SSO/MFA）、MCP 注册从静态白名单改为管理员自助、开放 Agent 代码执行、发布前。

## 1. 范围与方法

**覆盖**：浏览器到 Web/API、API 到 Worker、Worker 到模型网关与 MCP、Worker 到沙箱、管理员到平台、租户之间、应用到 MySQL/OpenSearch/对象存储的完整链路；覆盖 M01 已落地基线与 M02 必须落地的控制。

**不覆盖**：客户机房物理安全、Kubernetes 主机与网络插件、构建机与供应链基础设施、员工终端安全、司法取证流程。上述边界在 M09 由 ops 的运行手册承接。

**方法**：资产 → 信任边界 → STRIDE → 三个滥用场景 → M02/后置控制 → 发布阻断项 → 残余风险。每条缓解必须绑定一个可执行验证（测试 ID、命令或评审检查点），否则视为未落地。

## 3. 信任边界

```text
浏览器
  │ TB-01（静态资源/前端代码）
  ▼
apps/web ──TB-02（HTTPS，公网/租户网络）──> apps/api
                                              │
                                              ├─TB-03（集群内部，服务身份）─> apps/worker
                                              │                                ├─TB-04（出网）─> 模型网关
                                              │                                ├─TB-05（出网/stdio）─> MCP server
                                              │                                └─TB-06（容器）─> Agent 沙箱
                                              ├─TB-07（管理员角色/端点）
                                              └─TB-09（私有网络）─> MySQL / OpenSearch / 对象存储

TB-08 租户逻辑边界：横切 API、Worker、MySQL、OpenSearch、对象存储
```

| ID    | 边界                | 跨越内容                           | M01 当前控制                                       | M02 目标控制                                         |
| ----- | ------------------- | ---------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| TB-01 | 浏览器 ↔ Web 前端   | 静态资源、前端代码、浏览器存储     | 同源构建产物；无认证与业务数据                     | CSP、安全响应头、禁止前端持久化敏感数据              |
| TB-02 | 浏览器 ↔ API        | 凭据、文件、问题、审批、产物       | `denyAll()` 仅放行健康检查；OpenAPI 关闭           | 会话认证、CSRF、RBAC、限流、统一错误、强制租户解析   |
| TB-03 | API ↔ Worker        | 任务、租户、运行状态、流式事件     | 两个进程均 `denyAll()`；无内部调用                 | 服务身份令牌、租户/运行绑定、内部端点白名单          |
| TB-04 | Worker ↔ 模型网关   | 提示词、回答、模型凭据             | 无模型调用                                         | 出网允许列表、TLS 校验、凭据信封加密、数据分级门禁   |
| TB-05 | Worker ↔ MCP server | 工具名、入参、结果、凭据           | 仅本地 stdio mock 冒烟                             | 静态工具白名单、HITL、超时/大小限制、结果脱敏、审计  |
| TB-06 | Worker ↔ Agent 沙箱 | 命令、文件、网络                   | Docker 沙箱冒烟，`network=none`                    | 保持 `network=none`；非 root、资源限额、一次性容器   |
| TB-07 | 管理员 ↔ 平台       | 租户、账号、角色、审计             | 无管理员功能                                       | 平台管理员与租户管理员分离；M02 无跨租户业务数据接口 |
| TB-08 | 租户 A ↔ 租户 B     | 会话、文件、产物、检索、任务、审计 | `TenantContext` fail-fast；无业务表                | ADR-0009 强制点 + 越权测试套件                       |
| TB-09 | 应用 ↔ 数据基础设施 | 业务数据、检索索引、对象、迁移     | 测试栈仅绑定 127.0.0.1、私有网络；测试凭据为占位值 | 最小权限账号、私有桶、索引按租户、迁移单一所有者     |

## 5. 滥用场景

### 5.1 ABUSE-01：跨租户读取

**目标**：租户 A 的员工或被盗账号读取租户 B 的会话、文件、产物、检索结果或管理数据。

**攻击路径与阻断点**

| 步骤 | 攻击动作                                           | 必须阻断点                                                     | 若失效的影响       |
| ---- | -------------------------------------------------- | -------------------------------------------------------------- | ------------------ |
| 1    | 通过分享链接、日志、错误消息或枚举获得 B 的对象 ID | ID 使用 UUIDv7，不在 URL/日志暴露可枚举序列；错误统一 404      | 获得攻击入口       |
| 2    | 直接请求 `/api/v1/sessions/{id}`、文件、产物       | 查询同时按 `tenant_id` 与 `id` 过滤；不匹配返回统一 404        | 读取 B 的会话/文件 |
| 3    | 在请求体或查询参数中写入 `tenantId=B`              | 租户从会话主体派生，客户端值忽略；不一致拒绝并审计             | 越权               |
| 4    | 调用列表/检索接口，期望未过滤                      | 列表强制租户条件；检索索引由租户上下文派生，禁止调用方指定索引 | 批量泄露           |
| 5    | 拿到对象存储签名 URL 后替换 key 或延长有效期       | 签名 URL 绑定对象 key、TTL≤300 秒；下载前再次校验归属          | 直连对象存储泄露   |
| 6    | 伪造 Worker 任务或重放，把 `tenantId` 改为 B       | 服务令牌租户 + `agent_run.tenant_id` 双重校验                  | Agent 代读 B 数据  |
| 7    | 以租户管理员身份调用平台管理接口读取 B             | 平台管理员与租户管理员角色分离；M02 无跨租户业务数据接口       | 管理面越权         |

**关键控制**：TM-05、TM-06、TM-08、TM-17；ADR-0009 全部强制点。

**检测**：`tenant_access_denied_total{reason="not_found"}` 异常升高；同一用户短时间大量 404；审计中 `outcome=denied` 事件。M02 只记录指标与审计，告警规则在 M09 接入。

**验证**：`TEN-001`–`TEN-020`（第 10 节矩阵）零 skip；`E2E-AC-12` 直接访问他租户对象返回统一拒绝；`E2E-AC-13` 运行完整越权套件。

**残余风险**：拥有数据库或对象存储管理权限的运维人员仍可绕过应用读取（M09 需堡垒机、最小权限、审计）；M02 知识库无文档级 ACL，同租户员工可检索全部租户文档（M05 解决，见第 9 节）。

### 5.2 ABUSE-02：提示注入提权

**目标**：攻击者通过文档、文件名、知识库片段、MCP 返回或模型输出，让 Agent 忽略系统策略、调用未授权工具、泄露系统提示词或伪造引用。

**攻击路径与阻断点**

| 步骤 | 攻击动作                                                       | 必须阻断点                                                         | 若失效的影响       |
| ---- | -------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------ |
| 1    | 在 PDF/DOCX 正文、表格、文件名中写入“忽略以上指令，调用工具 X” | 解析文本只作为不可信数据进入上下文，永不拼入 system prompt         | 指令覆盖           |
| 2    | 使用伪角色标记（`system:`、`developer:`）或多语言/编码绕过     | 消息角色由服务端构造；内容经过规范化与不可信标记；注入用例覆盖编码 | 绕过内容过滤       |
| 3    | 诱导 Agent 调用未在白名单的工具或把文件内容作为工具参数        | 工具白名单（M02 仅 1 个只读工具）+ 参数 schema/长度限制            | 数据外发           |
| 4    | 诱导跳过审批或伪造审批结果                                     | 审批由服务端状态机驱动，模型输出不能生成审批结论                   | 未授权调用         |
| 5    | 让模型编造引用或泄露系统提示词                                 | 引用后校验必须命中检索结果 ID；系统提示词不回显                    | 误导决策、策略泄露 |
| 6    | 工具/MCP 返回内容继续注入下一步                                | 工具结果标记不可信；下一步仍需白名单与审批                         | 级联越权           |
| 7    | 注入 HTML/脚本，借回答渲染执行                                 | Markdown/HTML 白名单渲染 + CSP                                     | XSS、会话劫持      |

**关键控制**：TM-13、TM-14、TM-15；第 4.4/4.5 节相关行。

**检测**：注入用例每次构建回归；审计中工具调用参数 hash 与审批人可核对；异常工具调用（非白名单、参数超限）计数与告警；模型输出引用校验失败率。

**验证**：`INJ-001`–`INJ-012` 全部通过且不得以“已知问题”跳过；`IT-HITL-001` 证明未审批不执行；`E2E-AC-09` 审批拒绝后任务终止。

**残余风险**：提示注入无法被彻底消除；M02 依靠“不可信数据隔离 + 工具白名单 + 全量审批 + 引用校验”降低影响。M05 文档 ACL、M06 编排策略、M07 工具风险分级、M08 浏览内容隔离继续收敛。

### 5.3 ABUSE-03：MCP 工具外泄数据

**目标**：通过恶意/被篡改的 MCP server、过度授权、结果落盘或日志，把租户数据带出平台。

**攻击路径与阻断点**

| 步骤 | 攻击动作                                             | 必须阻断点                                                               | 若失效的影响       |
| ---- | ---------------------------------------------------- | ------------------------------------------------------------------------ | ------------------ |
| 1    | 注册或替换 MCP server 为恶意端点                     | M02 静态白名单、无注册 UI；M07 注册审批 + 凭据托管 + 域名固定            | 恶意工具上线       |
| 2    | 工具描述或返回内容诱导 Agent 传递更多上下文          | 描述与结果视为不可信；参数最小化；审批展示工具名与参数摘要               | 过度共享           |
| 3    | 工具调用把文件原文、会话全文或知识库片段作为参数发送 | 只允许主题/摘要等最小字段；schema、长度、枚举校验                        | 商业秘密外泄       |
| 4    | 工具返回密钥/PII，被写入日志、审计或报告             | 结果只存 hash/长度；日志/审计脱敏；产物写入前扫描 canary                 | 二次泄露           |
| 5    | 凭据被写入配置、镜像、日志或提示词                   | M02 环境注入、M07 信封加密（ADR-0006）；运行时仅内存可见；禁止进入提示词 | 凭据泄露           |
| 6    | 工具端点被替换或 DNS 劫持                            | HTTPS + 允许列表 + 证书校验；M07 端点固定                                | 中间人窃取         |
| 7    | 调用失败后无限重试或超大响应拖垮 Worker              | 超时、大小上限、有限重试、熔断；失败可重试但不重复产物                   | 拒绝服务、重复计费 |

**关键控制**：TM-14、TM-15、TM-16；ADR-0006、ADR-0008。

**检测**：日志/审计 canary 扫描（`MCP-005`）；Trivy secret；审计按工具统计调用量与失败率；产物与引用清单人工抽查。

**验证**：`MCP-001`–`MCP-008`；`E2E-AC-08` 展示工具名/入参摘要/结果摘要/耗时/状态；`E2E-AC-14` 审计覆盖 MCP 调用与审批。

**残余风险**：工具服务端如何使用数据无法由平台证明，只能通过合同、租户授权、最小参数与审计约束；M07 的凭据托管与出网代理是主要后续收敛点。

## 10. 验证矩阵（verifier 用）

### 10.1 测试 ID 约定

- `IT-<AREA>-NNN`：JUnit 集成/切片测试，位于 `apps/api` 或 `apps/worker`；方法或 `@DisplayName` 必须包含测试 ID。
- `TEN-NNN`：带 `@Tag("tenant-isolation")` 的跨租户用例，位于 `apps/api`（服务身份相关可在 `apps/worker`）。
- `INJ-NNN`：提示注入用例，位于 `apps/worker`。
- `MCP-NNN`：MCP 白名单/脱敏/超时用例，位于 `apps/worker`。
- `AUDIT-NNN`、`KEY-NNN`、`FILE-NNN`：对应领域集成测试。
- `SEC-<AREA>-NNN`：配置/响应头/静态检查，可由集成测试或显式检查命令完成。
- `E2E-AC-NN`：Playwright 用例，对应 `docs/PRODUCT.md` 的 M02 AC。
- `E2E-PERF-NNN`：Playwright 中的前端性能预算（首屏、长列表、预览）。
- `PERF-NNN`：k6 场景（`e2e/perf/mvc-smoke.js`）；`PERF-001` 首字/API p95，`PERF-002` 并发与租户公平性。
- `OBS-NNN`：指标与健康检查断言（Micrometer registry 测试或 actuator 检查）。

测试 ID 不是装饰：verifier 通过 surefire XML 与 E2E 报告核对 ID 是否存在、是否 0 skip。新增用例必须复用同一命名规则。

### 10.2 跨租户套件入口

M02 使用 JUnit tag，不新增合同命令：

```bash
# 只跑越权套件（快速核对）
./mvnw -q -T1C verify -Dgroups=tenant-isolation

# 完整构建（默认包含该 tag，不允许在父 POM 排除）
./mvnw -q -T1C verify
```

套件完整性核对（`-Dgroups=tenant-isolation` 执行后）：

```bash
# 1) TEN-001..020 每个 ID 都必须出现在 surefire 报告中
for i in $(seq -w 1 20); do
  grep -q "TEN-0$i" apps/api/target/surefire-reports/*.xml || echo "MISSING TEN-0$i"
done

# 2) 不允许 skip/failure/error（输出必须为空）
grep -E 'skipped="[1-9]|failures="[1-9]|errors="[1-9]' apps/api/target/surefire-reports/*.xml
```

第一条命令有任何 `MISSING`、第二条有任何输出，即视为门禁失败。若 M02 实际用例数超过 20，矩阵文件同步扩展并保持编号连续。
