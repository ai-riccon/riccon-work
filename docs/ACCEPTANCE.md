# 产品验收

本文件记录两层验收：

1. **Product 预验收**：实现是否按 `docs/PRODUCT.md`、UX 设计和范围落地；
2. **用户最终验收**：用户是否接受这个用户可见结果。

它不是 Verifier 的模块 review，也不是发布批准。Verifier 负责独立验证 AC、安全和行为；Product 不能替代 Verifier，用户保留最终接受权。

## Product 预验收（M03）

- 结论：`changes-requested`
- 需求一致性：目标用户、MVC、non-goals 与 `docs/PRODUCT.md` §1–§6 对齐；部门/成员/负责人、空间可见性、部门数据范围、知识库租户级共享明示、AC-19/20/21 部门段有真实证据。发现 3 个用户可见 AC 缺口（R-M03-01..03），修复后重新预验收；不把 AC-08..18（M10）算作 M03 通过。
- UX/文案：部门管理页可从“租户管理”导航直达；创建/成员/负责人/停用/启用；403“只有平台管理员可以管理部门”、404“目标租户或部门不存在”、409“目标租户已暂停”文案可读；成员抽屉的单主部门/负责人约束清晰。空间切换后会话/文件按空间加载并可继续；普通成员无“工作空间共享”入口。知识库共享范围固定明示；来源文件 404 文案明确。部门管理页 375px 无横向滚动、键盘可达、axe 无 serious/critical。
- 发现项：
  1. **R-M03-01（P2，AC-01）**：员工端没有“所属部门”展示。会话页/工作空间页只显示租户名与用户名；成员无法从界面确认自己属于哪个部门，也无法判断部门空间为何可见。
  2. **R-M03-02（P2，AC-02）**：部门空间没有重命名入口。共享抽屉只有创建、改可见性、CUSTOM 成员管理；负责人无法在界面上纠正空间名称（服务端 PATCH 已支持 name）。
  3. **R-M03-03（P2，AC-04）**：部门空间内报告不可见。研究页固定取第一个 ACTIVE 工作空间（通常为个人空间），没有工作空间选择或部门报告入口；E2E-M03-02 只覆盖会话/文件。
- 备注：F-006（P3）已接受；F-007/F-008/F-009 为 accepted/residual，见上表。REV-M03-001 的 AC-01/02/04 对账覆盖主路径，Product 按 AC 文本的用户可见结果补充判定为 fail，不否定 gate 证据。部门管理页 403 态只有“重试”，对非平台管理员不是有效下一步；建议后续改为“返回工作空间/联系管理员”，P3 不阻塞本次退回。

## 规则

- Product 预验收未 `pass` 前，不提交用户最终验收。
- 模块 gate 未通过前，不提交用户最终验收。
- 用户未 `accepted` 前，不进入下一个用户可见模块；最终产品验收未 `accepted` 前，不进入生产发布。
- `conditional` 必须列出条件和截止时间，并建立后续任务。
- 验收结论不替代 gate、release check 或生产批准。
