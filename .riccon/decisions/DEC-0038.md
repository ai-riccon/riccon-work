# DEC-0038：M05 检索 p95 2030ms 超 500ms：FTS/OpenSearch 还是接受残余

## 问题

空闲宿主/v2 索引复测（EV-0909，5000 文档/10 万 chunk/50 VU/45s）：检索 p95 2030ms > ADR-0023 §9 的 500ms；但首字估算 2126ms <3s、API p95 345ms <500ms，合同用户可见预算达标。ACL 写 p95 4188ms 受配额租户行锁影响（独立问题）。DEC-0035 规定检索 p95 >500ms 需另立决策。如何处置？

## 选项

- A：MySQL FULLTEXT/覆盖索引优化，检索仍以 MySQL 为权威；预计 8–12h，目标 p95 ≤500ms。ACL 租户锁另修。
- B：OpenSearch 检索 + 两阶段 ACL 复核；预计 16–24h，增加跨存储一致性与运维复杂度。
- C：接受当前检索 p95 ~2s 作为 M05 residual（用户可见首字/API 已达标），记录为 release blocker，M05 后优化。
- D：缩减数据量/检索范围或降低 AC（需正式缩范围）。

## 建议

A：FULLTEXT 成本低于 OpenSearch，能保留 MySQL 单库 ACL 权威并真正消除 2s 检索；若优先按期交付且接受 residual，可选 C。

## 后果

A 增加 8–12h 并需迁移/索引评审；B 增加 16–24h 与运维面；C 不阻塞 M05 但留下已知 4× 超标检索；D 改变已批准范围。

## 默认

无默认：检索预算超标属 T4 性能与范围决策，需用户明确选择。
