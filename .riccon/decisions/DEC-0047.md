# DEC-0047：M06 AC-23 回滚口径修订

## 问题

设计评审发现 AC-23 的“应用回滚到 M06 前版本且历史运行/审计仍可读”与现有架构冲突：旧 API 无 workflow 端点，且审计白名单对未知 workflow.* 动作 fail-closed。是否批准把 AC-23 的回滚口径改为可行的“关闭开关 + 回滚 Worker + 保留/前向修复 API；全量 API 回滚仅限无 workflow 数据/审计行”？

## 选项

- A（推荐）按可行口径修订 AC-23：受支持回滚 = 关闭 RICCON_WORKFLOW_ENABLED + 回滚 Worker + 保留/前向修复 API；关闭后历史运行与审计只读可查，J1/J2 正常；不做 down migration；全量 API 回滚仅限无任何 workflow 数据与审计行。
- B 保持 AC-23 原文，要求完整 API 回滚兼容；需额外兼容层/预发布补丁，重新评估预算与范围（可能 +8–16h，且削弱审计 fail-closed）。
- C 删除“应用回滚”AC，只保留 kill switch + Worker 回滚；降低 T4 回滚证据要求。

## 建议

A：这是现有审计 fail-closed 与旧 API 无 workflow 端点约束下唯一诚实、可演练的回滚口径；不改变用户可见功能，只把 AC 写成可验证事实。选 A 后由 Product 修订 AC-23，Verifier 重开可验证性评审。

## 后果

A 不增加预算，保留 T4 回滚证据；B 需要新的兼容设计、预算与发布流程，且旧 API 读未知审计动作会失败；C 会让 M06 的 T4 回滚证据不足。默认不批准则 M06 实现继续阻塞。

## 默认

不批准；M06 实现阻塞，等待明确选择。
