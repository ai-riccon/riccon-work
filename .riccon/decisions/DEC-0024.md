# DEC-0024：M04 拆分、预算与架构高成本项批准

## 问题

用户已通过 DEC-0023=A 批准 M04 范围。设计评审完成：Verifier REV-M04-ARCH-003 pass、Ops REV-M04-OPS-004 pass、Lead 检查 pass；ADR-0021/0022 仍 proposed。Architect 按 3 builder 重算：单模块 24h 不可行，建议拆 M04（路由/降级/多 key/端点；AC-01/03/04/05/06/07/15/16，8 条；12 任务；17-19h）+ M17（配额/成本/四页；AC-02/08..14/17/18，10 条；7 任务；14-16h；alias M04b，split_from M04，M04 用户验收 accepted 后启动）。请批准：1) 拆分与 AC 归属；2) 预算 M04 24h、M17 20h；3) V11 数据模型（新表/列/唯一键替换/全局表例外；model_invocation 无 FK；V11 不回溯 cost_day；quota 种子 false）；4) API 主密钥 current/previous/id/canary + fingerprint pepper（生产缺失即失败；丢失只影响新去重）；5) 生产必须配置 RICCON_MODEL_ENDPOINTS，否则启动失败；6) 准入即计费，失败/取消不退还，同 run 重试不重复扣；7) 默认限额租户日 10,000/月 200,000、用户日 1,000/月 20,000，0/NULL 不限，平台管理员写/租户管理员只读；8) 回滚窗口关闭 Worker schema 校验（仅回滚窗口，WARN+工单，不做 down migration）；9) 单币种 CNY/部署配置、M04 无价格编辑；10) /actuator/prometheus 仅内网 CIDR；11) AC-17 perf profile 50 并发/短超时/池≥25/假模型；12) M17 首发 quota false，B13 验证后 PUT true。是否批准？

- A 批准拆分 + 全部高成本默认值 + M04 24h/M17 20h（推荐）
- B 批准范围，但调整预算或模块 ID/拆分边界（回答中列明）
- C 不拆，M04 单模块 24h + 后移 P1 AC（需列明后移项；P0 不得后移）
- D 退回修改（说明要改的 ADR/AC）

## 建议

A：两份独立评审已 pass，3 builder 下拆分后各段均可在 24h/20h 内完成；单模块 24h 需 4 并行并压缩验证，不建议。
