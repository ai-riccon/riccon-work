# DEC-0029：M19 CI 取证：是否推送并运行 GitHub Actions

## 问题

M19 P3/P4 已完成，本地 4-shard 合并与 1115 用例全绿；TASK-0119 仍需真实 CI 证明 4-shard 后端墙钟 ≤5min。当前 main 领先 origin/main 257+ 提交，推送是对外副作用。是否授权推送并运行 GitHub Actions？

## 选项

- A 推送 main 到 origin/main，直接在 main 上跑 CI（最简单；会发布全部历史提交，CI 涵盖 backend shards/smoke/frontend E2E）
- B 推送临时分支 m19-ci-proof 并开 PR 到 main，通过 pull_request 触发 CI（推荐；不改 main，CI 通过后再决定合并）
- C 暂不推送，接受本地证据，M19 模块 gate 因 CI 墙钟未证而延后/blocked
- D 暂停 M19，等待进一步指示

## 建议

B：用临时分支+PR 获取真实 CI 墙钟与 shard/merge 行为，不先改 main；若 CI 失败可在分支上修复重跑，避免 main 被未验证状态污染。

## 后果

A/B 会消耗 GitHub Actions 分钟并公开提交；首次 CI 可能暴露与 M19 无关的远端/环境问题，需要按日志修复；C 不产生外部副作用，但 TASK-0119 的 CI ≤5min 验收无法完成，模块不能诚实 gate；D 暂停交付。

## 默认

C：不推送；保持本地证据，模块 gate 延后，等待明确授权。
