# DEC-0049：M06 运行准入 p95 预算与方案

## 问题

T16a PERF-M06-001 实测：A′ 配额锁修复后 M06 运行准入 p95=2588.6ms（基线 3394.4ms，预算 500ms；J1 首字 51ms，正确性/无 5xx 全通过）。是否修订 M06 性能口径、追加实现预算，还是保持 500ms 阻塞交付？

## 选项

- A（推荐）修订 M06 性能口径：读 API（列表/详情/保存/发布/历史）保持 p95 ≤500ms；运行准入写路径单列 p95 ≤3s（A′ 实测 2.59s），记录 residual，不追加 20–40h；Product 更新 AC-21/合同 performance，T16a 按新口径复跑。
- B 保持 500ms：另立 ADR 实现 reservation/异步计数/分片计数，预计 +20–40h，M06 延期；风险是仍可能不达标，且超过 20% 预算缓冲。
- C 保持 500ms 且不加预算/不延期：M06 gate 阻塞，不交付。
- D 分阶段：先按 A 交付 v1，M06b/M09 再做准入优化；AC 措辞同 A。

## 建议

A：A′ 已把 p95 降低 23.7%，J1 51ms、配额正确性/幂等/无 5xx 全通过；剩余瓶颈是租户日配额行 X 串行，不是缺陷而是设计取舍。B 需新 ADR + 20–40h 且不确定达标；C 阻塞交付。A 需 Product/Architect 同步 AC-21 与合同 performance，T16a 重跑并保留 residual。

## 后果

A/D：需改 AC-21/合同 performance，用户明确批准；T16a 以准入 p95 ≤3s + 读 API ≤500ms 复跑，记录 residual。B：+20–40h、新 ADR、M06 延期，可能仍不达标；不得静默超预算。C：M06 不交付。默认不批准则保持 500ms 且阻塞。

## 默认

不批准；保持 500ms，M06 gate 阻塞，等待明确选择。
