# DEC-0045：M11/M14 docs-only 遗留模块显式归档

## 问题

M11（planned，2/2 docs 任务 done）与 M14（building，3/3 docs 任务 done）是 0.1.9 之前的 docs-only 模块，没有模块 review/gate，且 0.1.15 的 8 项 DoD 需要 build/test/coverage/e2e 证据。为纯文档模块各跑一套全量测试成本高、不增加文档正确性证据。如何归一化？

## 选项

- A（推荐）：显式决策归档。把 M11/M14 标为 legacy blocked，记录 DEC-0045=A；保留任务/证据/评审历史，不声称模块完成或 Product/用户 accepted，不进入下一用户可见模块的解锁依据。
- B：补 docs-only 模块 gate。为 M11/M14 各跑合同 build/test/coverage/E2E，创建模块 review 并过 gate；约 1–2h，新增两套全量证据，Product/user 仍不自动 accepted。
- C：暂不处理。保留 state warning 与 M11 旧 next_action，只在 handoff 记录。
- D：其它（请说明归档方式或合并到其他模块）。

## 建议

A：两者均为旧流程的 docs-only 变更，任务证据和 M11 docs review 已存在；归档能消除 building/planned 的假活跃状态，同时不伪造 gate 或验收结论。

## 后果

A：M11/M14 进入 blocked/legacy 归档，next_action 指向真正的下一模块选择，历史保留；B：补两套全量证据与模块 review，gate 可过但成本高；C：warning 与旧 next_action 保留；D：按你的说明处理。

## 默认

无默认：模块状态归档属于显式治理动作，需用户明确选择。
