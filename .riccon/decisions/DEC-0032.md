# DEC-0032：M22 之后的下一模块：M20 fix 还是 M05 产品模块

## 问题

M22 完成后，下一模块选择哪条路线？M20 是 M04 残余修复（成本快照时点、成本查询保护、平台成本租户过滤、成本契约/AC-12 收口），不改变产品 AC；M05 是知识库纵深产品模块（Excel/图片/OCR、文档级 ACL、1 个外部连接器）。M16（Web 审计测试 flake）与 M14/M11 legacy closeout 仍待处理。

## 选项

- A M20 fix 优先（推荐）：先关闭 M04 残余的正确性/租户过滤项，再开 M05；M20 预算 4h，不改变产品范围。
- B M05 产品模块优先：直接进入知识库纵深；M20 残余继续跟踪。
- C 先做 M16 + M14/M11 legacy closeout：先清 flake 与状态债务，再选 M20/M05。
- D 暂停：保持 M22 done，等进一步安排。

## 建议

A：T4 下 M04 残余包含平台成本租户过滤与查询保护，due 在 M05/M20 gate 前；先做 M20 风险更低，再开用户可见的 M05。

## 后果

A 先技术收口，M05 延后；B 产品进度优先，M04 残余风险继续存在；C 清债但产品进度延后；D 无新工作。

## 默认

A（M20）：可逆的模块顺序决策；若用户在截止前不反对，按 A 执行。
