# DEC-0043：M25 性能复验：ACL 写 p95 residual

## 问题

B11b 1000 对象连接器场景：sync 41.7s、检索 p95 40ms、首字 49ms、队列等待 50.6s 均达标；整条 matrix 唯一失败是 ACL 写 p95 2.98s > 500ms（既有 quota 租户行锁 residual，历史 4.3–4.6s）。DEC-0039=A 约定在 M05b gate 前决定修复或再次书面接受。如何处理？

## 选项

- A（推荐）：再次书面接受 ACL 写 residual（管理员非聊天热路径），owner Lead+Architect 跟踪到 M09/发布；M25 gate 记录 accepted residual，不新增预算。
- B：M25 内新增 fix 任务修复 ACL 写 ≤500ms（估 4h），M25 预算 56h→60h，V1b/V2b 延后；需新任务与回归。
- C：接受为 M09/release blocker，不阻塞 M25 gate；M09 必须解决或再次书面接受，release 前不得静默放过。
- D：其它（请说明）。

## 建议

A：连接器与聊天/检索/首字均达标；ACL 写是管理员低频操作，既有 DEC-0039 已接受，重复修复性价比低；但必须在 M25 评审与发布记录中保留 owner/due，不声称已修复。

## 后果

A：M25 gate 可带 accepted residual；B：新增 4h 与任务，V1b/V2b 延后；C：M09/release 阻断项，M25 可继续；D：按你的说明处理。

## 默认

无默认：T4 性能 residual 需用户明确接受或修复。
