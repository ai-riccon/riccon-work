# DEC-0028：M19 P2 后 CI 墙钟口径与推进方式

## 问题

M19 P2 的 4-shard 已完成本地验证（193 类/1101 用例，0/0/0；最大分片 test 墙钟 294s），但 CI job 墙钟估算 6–8 分钟，超过模块 AC 的“后端墙钟 ≤5 分钟”，且 GitHub Actions 尚未运行。应如何推进？

## 选项

- A 保持 AC 为 CI job ≤5min；先做已批准的 P3（构建产物共享/预构建 runner 镜像），P3 后再单独申请 push/CI 取证（推荐）
- B 保持 AC 不变，立即授权 push 到 origin/main 触发 GitHub Actions，用真实 CI 数据决定是否需要 P3（对外副作用；本地领先远端 257 个提交）
- C 将 AC 明确为 4-shard test 阶段 ≤5min（当前 294s 达标），CI job 6–8min 作为残余风险，继续 P3 优化但不阻断模块
- D 暂停 M19，等待进一步分析

## 建议

A：不改变已批准的 AC 口径，也不在未验证 P3 前 push 257 个提交；P3 已由 DEC-0026 批准，先降低重复冷编译/镜像与 setup 成本，再 push 一次测量，减少无效 CI 运行和对外副作用。

## 后果

选 A/C 则继续 M19 P3/P4，P2 任务保持 review 或按新口径关闭；选 B 会推送当前 main 并触发 CI，可能暴露与 M19 无关的远端/CI 问题；选 C 需同步修订模块 AC 与文档，‘CI job 6–8min’作为残余风险记录；选 D 模块暂停，不启动 P3/P4。

## 默认

A：不 push，保持 AC 原义，先做 P3，P3 后再单独申请 CI 取证。
